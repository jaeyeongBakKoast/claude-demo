# 보안 점검 (시큐어코딩·웹 취약점)

> 기준 문서는 사업의 과업지시서가 정한 것을 따른다. 공공 SW는 보통 행정안전부 「소프트웨어 개발보안 가이드」와
> 「소프트웨어 보안약점 진단가이드」, 웹 취약점은 발주기관 또는 KISA 점검 기준을 쓴다. **항목 목록은 최신 가이드에서 옮겨 온다.**

## 점검 방법

| 구분 | 도구·방법 | 시점 | 결과 보관 |
|---|---|---|---|
| 시큐어코딩(정적 분석) | <발주기관 지정 도구 또는 SpotBugs+FindSecBugs, Semgrep 등> | 보안 영향 스토리, 단계 말 | `docs/quality/security/<YYYY-MM-DD>-sast.md` |
| 웹 취약점(동적 점검) | <점검 도구, 모의해킹> | 시험 단계 | `docs/quality/security/<YYYY-MM-DD>-web.md` |
| 코드 리뷰 | `security-reviewer` 에이전트 | 인증·인가·외부 노출 API 변경 스토리 | 스토리 `review.md` |

## 스토리 단위 체크 (리뷰 때 해당 항목만)

| 분류 | 확인 |
|---|---|
| 입력 검증 | SQL은 `#{}` 바인딩, 경로 조작(`..`) 차단, 업로드 확장자·크기 제한 |
| 인증·인가 | 새 엔드포인트가 보안 설정에 등록됨, 권한 검사가 서버에서 수행됨 |
| 오류 처리 | 스택 트레이스·내부 경로가 응답에 노출되지 않음 |
| 암호·비밀값 | 비밀번호 단방향 해시, 키·비밀번호가 코드·로그·설정에 없음 |
| 세션 | 로그아웃 시 세션 무효화, 쿠키 `HttpOnly`·`Secure` |
