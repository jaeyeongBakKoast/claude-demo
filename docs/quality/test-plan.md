# 시험 계획서

## 시험 단계

| 단계 | 대상 | 방법 | 수행 | 결과 기록 | 통과 기준 |
|---|---|---|---|---|---|
| 단위 시험 | 서비스·유틸 단위 | JUnit 5, pytest, vitest | 개발자 (스토리마다) | `generated/unit-test-report.md` | 실패 0건 |
| 통합 시험 | 스토리 수용 기준, 모듈 간 연계(IF) | 시나리오 수행 | 개발자 (story-review) | [integration-tests.md](integration-tests.md) | 수용 기준 전부 통과 |
| 시스템 시험 | 비기능 요구사항 (성능·보안·접근성) | 도구·체크리스트 | <담당> (단계 말) | performance, security, web-accessibility | `REQ-N` 측정 기준 충족 |
| 인수 시험 | 요구사항 전체 | 발주기관 입회 시연 | 발주기관 | <인수 시험 결과서> | 발주기관 승인 |

## 시험 환경

| 구분 | 구성 | 비고 |
|---|---|---|
| 개발 | 로컬 + docker compose DB | |
| 시험 | <서버, OS, DB 버전> | 운영과 같은 버전 |

## 결함 관리

- 결함은 <이슈 트래커>에 등록하고, 수정 스토리 또는 수정 커밋에 결함 번호를 적는다.
- 심각도: 치명(서비스 불가) / 높음(주요 기능 오류) / 보통 / 낮음(표시 오류).
- 인수 시험 전까지 치명·높음 결함 0건.
