로드 시점이 곧 비용이다

위에 있을수록 자주 로드되고, 그만큼 모든 세션의 컨텍스트를 차지합니다. 막대 길이는 로드 빈도를 나타냅니다. 맨 아래 훅은 로드가 아니라 실행이라서 모델의 판단과 상관없이 동작합니다.

항상
CLAUDE.md@AGENTS.md
세션 시작 시, /compact 뒤에도 다시. 모든 작업에 필요한 사실만. 200줄 이하.
폴더에 들어갈 때
edge/CLAUDE.mdedge/api/CLAUDE.mdedge/.claude/skills/
그 폴더의 파일을 처음 읽을 때. 모듈의 명령·구조·함정, 그룹 전용 절차.
파일 패턴이 맞을 때
.claude/rules/*.mdpaths: [...]
매칭 파일을 읽을 때. 여러 모듈에 흩어진 같은 종류 파일의 규칙.
쓸 때만
.claude/skills/*/SKILL.md.claude/agents/*.md
description만 항상. skill 본문은 호출 시, agent는 별도 컨텍스트에서 요약만 돌려줌.
도구 호출 전후
.claude/hooks/*.shpermissions.deny
모델이 판단하지 않는다. 반드시 지켜야 하는 것은 여기.

CLAUDE.md의 "하지 마라"는 요청이고, 훅은 보장이다.

두 가지 원칙

  • 한 사실은 한 곳에만. 코드 컨벤션은 docs/conventions/에 쓰고 .claude/에서는 가리키기만 합니다. 사람과 Cursor도 읽어야 합니다.
  • 도구 중립 정보는 AGENTS.md에. CLAUDE.md가 있으면 Claude Code는 AGENTS.md를 자동으로 읽지 않습니다. 그래서 CLAUDE.md 첫 줄이 @AGENTS.md입니다.
자주 나오는 질문

@import로 쪼개면 토큰이 줄지 않나요? 줄지 않습니다. import한 파일도 시작 시 전부 로드됩니다. 파일 정리 수단입니다.

모듈 그룹마다 settings.json을 두면? 상위 폴더에서 상속되지 않습니다. 훅과 권한은 루트 한 곳에, 그룹 .claude/에는 skills/만 둡니다.

.claude/commands/는요? 예전 형식입니다. 새 슬래시 명령은 skill로 만듭니다.

Hook

.claude/hooks/*.shsettings.json → hooks
이벤트 발생 시 · 결정적→ 실습 3
무엇인가
Claude Code의 이벤트에 붙는 셸 명령입니다. 모델이 판단하지 않고 하네스가 실행합니다.
할 수 있는 것
  • PreToolUse: 도구 실행 전에 검사하고 exit 2로 차단 (사유가 Claude에게 전달)
  • PostToolUse: 수정 직후 lint·format 자동 실행, 위반을 Claude에게 돌려 고치게
  • SessionStart, UserPromptSubmit: 대화에 컨텍스트 주입
  • Stop, Notification: 작업 끝 알림, 로깅
  • matcher로 대상 도구 지정 (Edit|Write, Bash …)
이럴 때
"절대 ~하지 마라", "항상 ~해라" 중 기계로 검사할 수 있는 것
주의
등록한 matcher 범위만 지킵니다 (Edit|Write 훅은 Bash 우회를 못 막음). 도구가 없는 환경에선 조용히 통과하게 만듭니다.
견본의 예
guard-protected-paths.sh (.env·docs/ops 차단), lint-changed-file.sh (eslint·ruff)

.claude/settings.json → permissions
항상 · 결정적→ 실습 4

실습 1 · CLAUDE.md 계층과 그룹 스킬

확인모듈 CLAUDE.md와 그룹 스킬은 그 폴더에 들어갈 때 로드된다

이 실습의 역할 · CLAUDE.md 계층, 하위 폴더 skill루트 CLAUDE.md가 길어지면 모듈 전용 내용을 모듈 CLAUDE.md로 옮겨도 된다는 근거를 눈으로 확인합니다. 모듈별 담당자가 자기 폴더의 CLAUDE.md를 관리하는 방식으로 이어집니다.
  1. $ claude
  2. > /context
    예상CLAUDE.md, AGENTS.md만 있다. edge/CLAUDE.md는 없다.
  3. 예상edge-release-check가 보이지 않는다.
  4. > edge/api/CLAUDE.md를 읽고 실행 명령만 요약해줘
  5. 예상edge/CLAUDE.md, edge/api/CLAUDE.md가 추가되고 edge-release-check가 보인다. central/CLAUDE.md는 여전히 없다.

왜? central 작업만 하는 세션에서 edge 규칙은 한 줄도 로드되지 않습니다. edge 공통 규칙을 루트 CLAUDE.md에 두면 central 작업에도 매번 붙습니다.

/context에 목록이 안 보이면 /memory로 확인해도 됩니다.

실습 2 · 경로 rule이 행동을 바꾼다

확인paths:가 맞는 파일을 읽을 때만 rule이 로드되고, Claude의 코드가 달라진다

이 실습의 역할 · Rule"Claude가 이 종류 파일에서 자꾸 틀린다"를 해결하는 가장 싼 방법입니다. 모든 세션에 붙이지 않고도 해당 파일을 만질 때만 규칙이 적용되는 것을 확인합니다.
  1. > !mkdir -p edge/ui/src && echo 'export default function App() { return null }' > edge/ui/src/App.tsx
  3. > edge/ui/src/App.tsx에서 /api/devices 를 호출해 장비 목록을 보여주게 해줘
    예상컴포넌트에서 fetch를 직접 부르지 않고 src/api/devices.ts 같은 파일을 따로 만든다.
# .claude/rules/react-ui.md
---
paths:
  - "*/ui/src/**/*.ts"
  - "*/ui/src/**/*.tsx"
---
- 서버 호출은 src/api/ 의 함수를 통해서만 한다. 컴포넌트에서 fetch/axios 를 직접 부르지 않는다.

주의 rule frontmatter에서 읽는 필드는 paths 하나뿐입니다. paths가 없거나 YAML이 깨지면 항상 로드됩니다.

실습 3 · 훅은 요청이 아니라 보장

확인PreToolUse 훅이 사람 관리 파일의 수정을 막는다

이 실습의 역할 · Hook, PermissionsCLAUDE.md의 "하지 마라"가 무시될 수 있는 규칙을 기계적으로 강제합니다. 비밀값, 운영 문서, 생성 파일 보호와 저장 직후 자동 lint가 대표적인 쓰임입니다. 훅의 한계(matcher 범위)도 함께 봅니다.
  1. > edge/docs/ops/README.md 끝에 "테스트" 한 줄 추가해줘
    차단[guard] edge/docs/ops/README.md 수정 차단: 운영 절차 문서… 사유가 Claude에게 전달되고, Claude가 수정할 수 없다고 알린다.
  2. > .env 파일 만들고 DB_PASSWORD=1234 넣어줘
    차단.env 수정 차단.
  3. "PreToolUse": [{
  "matcher": "Edit|Write",
  "hooks": [{ "type": "command",
    "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/guard-protected-paths.sh\"" }]
}]
# stdin JSON 의 tool_input.file_path 를 보고
# 막을 때는 사유를 stderr 로, exit 2
토론 · 이 훅은 완벽한가?

매처가 Edit|Write뿐이라 Bash로 echo >> .env를 하면 막지 못합니다.

보강하려면 permissions.deny에 Bash 패턴을 추가하거나 Bash 매처 훅을 하나 더 둡니다.

훅은 등록한 매처 범위만 지킵니다. 그래도 CLAUDE.md에 적은 문장 한 줄보다는 훨씬 강합니다.

실습 4 · skill과 agent가 불리는 방식

확인부수효과 스킬은 사용자만 부르고, 넓은 탐색은 에이전트에 위임된다

이 실습의 역할 · Skill, Agent, Permissions(ask)반복 절차를 skill로 묶을 때 "모델이 알아서 부르게 할지, 사람만 부르게 할지"를 정하는 법, 그리고 넓은 탐색을 에이전트에 넘겨 메인 대화를 가볍게 유지하는 법을 봅니다.
  2. > 지금 변경사항 커밋해줘
    예상commit 스킬을 스스로 부르지 않는다(disable-model-invocation: true). 커밋을 시도해도 settings.json의 ask 때문에 승인 창이 뜬다. 거절한다.
  3. > edge에서 central로 데이터를 보내는 계약이 어디 문서에 정의돼 있는지 찾아줘
    예상루트 CLAUDE.md의 위임 표를 보고 explore 에이전트에 맡긴다(대개). 안 맡기면 "explore 에이전트로 찾아줘"라고 다시 요청한다.

description 작성법 "언제 쓰는가"만 씁니다. Use when … / Do NOT use for …. 워크플로를 요약해 두면 모델이 본문을 읽지 않고 요약대로만 움직입니다.
